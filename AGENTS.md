This is the project's AGENTS.md

- Treat the repository as part of the model context. Bad context creates bad research. Delete or rewrite stale, contradictory, weakly-supported, duplicated, or archaeology-only guidance as soon as it is found. Do not preserve it "just in case". Git is the archive.
- Read `tracker.md` and run `.\lab.ps1 status` before research work. `tracker.md` owns compact scientific state; `research-cycle.json` owns machine-readable cycle/config. The lab should repair mechanical drift such as the cycle-status marker automatically. Stop only for substantive scientific/config disagreement.
- Think from the measured failure before reading papers or copying an existing tracker. Generate several mechanisms first, including one intentionally simple/weird idea, one removal/inversion, and one state/learning reformulation. Literature is for falsification and implementation help, not for choosing the search space.
- Probe slots are a brake on repeated heldout/dev peeking, not a tax on learning. Train-only no0096 development under `diagnose` may train real learned mechanisms and does not consume a formal probe slot. A cycle has at most three optional decision-changing probes (`mechanism`, `reality`, `break-it`); use only the ones that can change the decision and stop early when evidence is decisive. A big run is earned, never mandatory.
- **Never close a learned family from a smoke run or an under-trained run.** A 100/300/500-step negative means "negative at this scale" unless there is a hard information ceiling or deployment contradiction. Finish the planned compute. If the primary metric is still materially improving late in the run, the next question is a scale test, not an automatic kill.
- A family may be called **closed** only for a hard reason: the required information is absent/has a measured ceiling below target, the mechanism violates the deployment contract, or a fair scaling curve has clearly saturated after the real mechanism learned. Otherwise use `under-tested`, `negative at this scale`, or `superseded`, not `closed`.
- Small parameter sweeps are not scaling research. More width, one threshold, one loss weight, or one extra head is not evidence of an emergence curve. Scale compute/data/context on the actual mechanism while keeping the question stable.
- A big run must train the deployable mechanism on meaningful causal rollouts and model-owned state. Do not shrink a bold hypothesis into a frozen-feature toy merely because it is easier to run.
- Permanent public identity authority must stay independent of corruptible spatial observations. Public IDs normally do not recycle; stale coast boxes are never published.
- `dancetrack0096` is an architecture gate, never training data. Four final holdouts remain untouched. Clean RT-DETR lineage: `runs/expanded-0002/last.pt`. Clean long manifest: `data/manifest-train-full-dense-no0096.json`.
- Use `.venv\Scripts\python.exe`. Run only one GPU-heavy job at a time. Do not reset, clean, or discard unrelated dirty work.
- Lab subprocesses are resource-guarded: numerical CPU threads are capped, research runs at below-normal priority, and the lab pauses its process tree when whole-system CPU reaches 90%, resuming below 80%. Keep heavy work behind the lab front door instead of bypassing this guard.
- Use the `lab.ps1` front doors when they fit. They run their own safety preflight, so do not ritualistically rerun doctor/test before every action. `diagnose <name>` is the guarded train-only scratch lane under `runs/_diag_<name>/probe.py`; learned training is allowed there. Archive durable evidence under `runs/` and remove scratch after interpretation.
- Preserve strict checkpoint loading and nonpersistent position-embedding buffers. Frozen-feature caches are valid only for deterministic preprocessing and frozen eval-mode image features.
